# Project name

One sentence describing what the project does and who uses it. State whether it is a library, application, service, or internal tool.

## Status

Describe what is working today and link to the current release or environment only when verified. Keep planned work separate from shipped functionality.

## What it does

List the main user-facing capabilities. Avoid marketing claims that the implementation does not support.

## Architecture

Explain the important components, data flow, external services, and where the application runs. Add a small diagram when it makes the system easier to understand.

## Requirements

List supported runtimes, tools, services, and versions needed for local development.

## Getting started

Give exact steps to obtain dependencies, configure the local environment, prepare required data, and start the application. Never include real credentials or personal data.

## Configuration

Document each required and optional environment variable, its purpose, and a safe example value. Link to a local example file when one exists.

## Development

Describe the repository layout and the normal local workflow. Keep commands copyable and explain where they should be run.

## Verification

List the checks that actually run for pull requests and the commands contributors can run locally. Separate automated results from manual, preview, and production checks.

## Release and deployment

Describe how a reviewed change reaches its target environment, required migrations or configuration changes, the post-release verification, and the rollback path. Do not claim that a merge proves a deployment.

## Security and privacy

Explain how to report a vulnerability, how secrets are handled, and which sensitive data the application processes. Do not put secrets, private keys, database exports, or personal data in Git.

## Limitations

Record known gaps, unsupported scenarios, and dependencies that can affect operation. Remove outdated limitations when they are fixed.

## Related projects

Link only to active, relevant repositories and services.
